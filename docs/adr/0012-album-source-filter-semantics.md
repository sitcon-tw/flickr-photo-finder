# ADR 0012: 來源相簿篩選語意與照片 metadata 邊界

## 狀態

Accepted

2026-11-07 經專案維護者確認採用。目前實作與操作規格以 [公開前端架構](../public-frontend-architecture.md) 為準。

## 背景

公開 Finder 的「活動/相簿」選項以相簿 ID 篩選照片，將年份、活動與相簿名稱組成顯示文字。這能服務已知相簿的使用者，但跨年份找同類活動、找某一年所有活動時，仍需逐本挑選相簿。

[資料模型](../google-sheets-database-design.md) 允許同一張照片屬於多本相簿；[schema](../../data/photo-schema.json) 也分別保留照片與相簿的活動名稱、年份。拆分來源控制項時，需要明確區分兩張表的語意，避免介面、排序與 AI 交接各自推導不同的活動歸屬。

## 決策

### 來源範圍依相簿的活動歸屬判斷

- 將年份、活動與相簿設為同一組來源篩選面向；年份與活動取自 `albums`，透過 `photos.album_ids` 連接照片。
- 年份代表來源相簿的活動歸屬年，不代表拍攝或上傳年份。活動沿用正式相簿資料中的分類，不自行合併名稱或由標題推測分類。
- `album_title` 負責顯示與選項文字搜尋，`album_id` 負責識別。重名相簿保持分開，選項與已選條件均須能區分。
- 照片自身的活動欄位保持原意，即使日後與來源相簿不同，這組篩選仍查詢相簿脈絡。推導結果只作查詢脈絡，不覆寫照片原始欄位或回填正式 Sheets。

這項選擇讓活動脈絡集中由相簿維護，也接受同一張照片可以在不同來源範圍中被找到。

### 多相簿照片須由同一來源完整符合條件

同一欄位內多選取聯集，不同來源欄位之間取交集。先找出同時符合年份、活動與相簿條件的來源相簿，再找出屬於其中任一本的照片；結果與照片總數以 `photo_id` 去重。

例如照片 P 同時屬於「2025 Camp」與「2026 年會」：

| 來源條件 | P 是否命中 | 原因 |
| --- | --- | --- |
| Camp，年份不限 | 是 | 有 Camp 來源相簿。 |
| 2025，活動不限 | 是 | 有 2025 來源相簿。 |
| 2025＋Camp | 是 | 同一本相簿完整符合。 |
| 2025＋年會 | 否 | 沒有同一本相簿完整符合。 |
| 2025 或 2026，活動不限 | 是，計一張 | 多個相簿命中仍是同一張照片。 |

不能把照片所有來源的年份與活動分別攤平成集合後獨立比對，否則會產生不存在的活動與年份組合。既有 canonical 相簿承擔分組與排序，並不限制其他來源被搜尋。

### 缺失資料與無效條件不得造成隱性放寬

- 未設定來源條件時，來源篩選不額外排除任何照片；其他搜尋與篩選條件照常套用。
- 未知值也依同一來源的任一命中規則判斷：某來源的欄位未填或無法連接目錄，即可滿足該欄未知，其他來源條件仍須由同一來源滿足。無相簿 ID 的照片可由未知來源入口找到，其來源活動與年份均視為未知。
- 欄位未填、無相簿 ID、ID 不在目錄中須保留不同的缺失原因。未知狀態不使用可能與真實活動名稱撞名的文字值表示。
- 若照片仍記錄某個相簿 ID，但目錄沒有該筆資料，直接指定該 ID 仍可依成員關係找到照片；其活動與年份保持未知，不從照片欄位或相簿名稱補值。
- `album` URL 條件只接受 `id:<album_id>` 與表示無相簿 ID 的 `missing:`。相簿名稱僅用於顯示與選項搜尋；`title:` 或未加前綴的值不參與來源比對，不推測或轉換成相簿 ID。
- 分享連結中的值即使不在選項清單內，仍須保留在狀態與已選條件中。若沒有相符索引照片，顯示原因與解除入口，不得刪除條件後顯示較廣的結果。

上述規則保留可探索的照片，也維持 [ADR 0007](0007-finder-index-results-are-not-absence-proof.md) 的邊界：未命中索引不代表 Flickr 沒有相關照片。

### 選項連動保留使用者意圖

- 沿用既有可搜尋多選控制項、finder state 與逐值條件標籤；使用者可以從任一來源欄位開始。
- 來源選項以索引照片記錄的來源為基礎，不將尚無索引照片的目錄相簿新增為候選；已選值另予保留。可用性套用其他搜尋與篩選條件，排除該欄自身限制，讓同欄仍可擴大多選。
- 選相簿不自動加入年份或活動條件；改變其他條件也不自動清除已選值。
- 已選值即使沒有結果，仍可辨識與移除。「清除來源」只清這組條件，保留文字搜尋、工作用途、畫面條件、排序與候選清單。
- 衝突恢復建議須以實際索引照片驗證。若顯示放寬後的結果數，須包含其他搜尋與畫面條件，不能只憑相簿目錄有候選就宣稱能恢復照片結果。
- 正式結果總數計算不同 `photo_id`，不能加總 `albums.photo_count`。逐選項照片計數延後；若後續加入，也須套用其他條件、排除自身欄位並去重。

### 年份基礎排序使用同一來源脈絡

「年份新到舊／年份舊到新」的基礎排序改依來源年份，與來源篩選同次驗收發布；既有分享候選置頂的優先序維持不變。每張照片的代表來源依下列規則選擇：

1. 從該照片的來源相簿中，保留完整符合目前來源條件的相簿；沒有來源條件時保留全部來源。
2. 沿用既有 `albums` 目錄順序，取第一本作為代表來源。若沒有符合來源條件且可連接目錄的相簿，其排序年份為未知。
3. 使用代表來源的活動年份；若該欄未填，不跳到另一本相簿補值。未知年份在兩種排序方向都置末，同年份維持來源 `photos` 列順序。

因此同張照片在不同來源範圍下，代表年份可能不同；此取捨讓排序回應目前的找圖脈絡。預覽應能辨識這個來源脈絡，並與照片自身欄位分開呈現。預覽細節載入不得改變既有篩選結果或排序。

本決策只調整明確的年份排序，不連帶改寫推薦權重或探索分散政策，也不以寫入 `photos.event_year` 的方式共用推導值。

### 分享與 AI 交接使用相同的來源解析結果

- Finder 分享連結保存使用者選擇的三欄條件，開啟時依當下索引解析；它重現查詢條件，不承諾在資料更新後仍是完全相同的照片集合。
- AI 提示詞保留人類可讀的來源條件，並附上前端已解析的相簿 ID 範圍與是否允許無相簿 ID，讓 AI 依照片的 `album_ids` 重現來源範圍，不把同一條件套到照片自身的活動欄位。
- 相簿 ID 與無相簿 ID 分支取聯集，再套用其他照片條件；解析後沒有候選來源與未設定來源限制必須區分。
- AI 交接反映複製時的索引；重新探索其他來源時需重新解析，不能把該 ID 清單視為永久活動分類。

## 實作範圍與文件歸屬

首次交付維持桌面搜尋與篩選的既有兩列結構：第一列依序為「搜尋、活動、年份、相簿、排序」，第二列沿用既有用途與畫面等篩選。三個來源欄位直接整合到第一列，不另外增加來源範圍列；排列順序不限制使用者從任一欄開始。手機沿用既有篩選面板，依上述規則完成篩選、年份排序與分享整合。展開探索面板、額外相簿預覽、整頁重排、逐選項照片計數與推薦／探索政策調整均延後。

實作時，filter key、URL key、顯示文字與分組放回 [interface registry](../../data/interface-registry.json)，依 [共用值治理](../shared-value-governance.md) 同步衍生設定。操作現況更新到 [公開前端架構](../public-frontend-architecture.md)，來源邊界同步到 [資料庫設計](../google-sheets-database-design.md) 與 [AI 讀取文件](../ai-readable-dataset.md)。本 ADR 保存決策理由，不另建欄位規格或選項清單。

## 驗收邊界

以可重現的照片案例驗證上述來源、未知值、無效條件、排序與交接規則，包含多相簿反例及分享候選置頂。runtime CSV 與 static-sharded 須得到相同結果，另完成桌面兩列配置、長相簿名稱、鍵盤、焦點、手機與大量照片效能驗證；具體檢查指令沿用前端架構的驗證門檻。相簿層原型檢查不取代正式照片層驗收。

## 取捨與替代方案

| 選擇 | 收益 | 代價或未採用原因 |
| --- | --- | --- |
| 採相簿來源語意，保留照片原始 metadata | 支援跨年活動探索，避免逐張複製相簿脈絡。 | 必須明確顯示兩種脈絡，並維護跨介面一致性。 |
| 任一完整符合的來源都可命中 | 多相簿照片可從不同工作脈絡被找到。 | 同圖可能出現在不同年份或活動查詢中，需去重並解釋排序。 |
| 維持單一「活動/相簿」選單 | 不增加控制項。 | 跨年與跨活動需求仍需逐本選相簿。 |
| 直接改查照片自身的活動欄位 | 可沿用單值欄位比對。 | 查詢的是照片 metadata，無法完整表達多個來源相簿的活動歸屬。 |
| 只依 canonical 相簿搜尋 | 每張照片只有一個來源分類。 | 漏掉其他真實相簿成員關係，不符合跨來源找圖目標。 |
| 以相簿名稱建立來源關聯 | 可直接輸入名稱查詢。 | 名稱可能重複或變更，不能穩定識別來源，故只以 ID 比對。 |
| 自動補選年份或清除衝突 | 減少部分手動操作。 | 增加隱藏限制或改動使用者意圖，難以解釋分享結果。 |

## 重新評估條件

- 真人找圖案例顯示主要需求是照片自身的活動身份，或需要固定且唯一的來源分類。
- 跨年相簿、精選集或回顧相簿增加，使來源年份經常被誤解為拍攝年份。
- 活動分類出現需要治理的同義名稱或層級，已無法只沿用相簿既有值。
- 使用者仍難以理解代表來源、未知值或條件衝突，需要調整互動方式。
- 正確性與效能驗證完成，且實際需求足以支持逐選項照片計數或展開探索面板。
